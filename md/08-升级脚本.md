# Companion 模块开发 - 升级脚本 (Upgrade Scripts)

> 文档来源：https://companion.free/for-developers/module-development/connection-basics/upgrade-scripts

## 概述

随着模块功能迭代，有时需要更改现有动作或反馈的实现方式。升级脚本的作用是在模块更新后，修复用户已在配置中使用的动作和反馈，使其兼容新版本。

## 暴露升级脚本

### API 2.x

在 `src/main.ts` 中导出：

```typescript
export const UpgradeScripts = [....]
// 或
export { UpgradeScripts } // 从其他文件导入
```

### API 1.x

通过 `runEntrypoint()` 的第二个参数传递：

```typescript
import { upgradeScripts } from './upgrades'
runEntrypoint(MyModuleClass, upgradeScripts)
```

建议将升级脚本定义在单独的 `src/upgrades.ts` 文件中，避免主类文件过长。

## 测试升级脚本

推荐测试流程：
1. 在添加升级脚本前，先构建一页测试配置
2. 反复重新导入该页面，每次都会重新运行升级脚本

**注意**：备份配置或使用可丢弃的测试配置，因为其他页面的按钮可能已经运行过一次升级脚本。

## 编写升级脚本

每个升级脚本对每个动作和反馈只会运行一次，但建议编写可安全多次执行的脚本，便于测试或在 Companion 版本间切换。

简单示例：

```typescript
const UpgradeScripts = [
  function example_conversion(context, props) {
    const result = {
      updatedConfig: null,
      updatedSecrets: null,
      updatedActions: [],
      updatedFeedbacks: [],
    }

    for (const action of props.actions) {
      if (action.actionId === 'test') {
        // 修改选项值
        action.options.value = action.options.value + 1
        // 告知 Companion 此动作已更改
        result.updatedActions.push(action)
      }
    }

    return result
  },
]
```

**警告**：一旦定义了升级脚本，不要移除它。如果减少了脚本数量，Companion 会为某些用户跳过下一个添加的脚本（Companion 会计数已运行的脚本数量）。

## 脚本参数

### context 参数

目前包含一个属性 `currentConfig`，描述实例当前的用户配置状态。此对象不可修改，仅作参考。如需更新配置，应在 `props` 中处理。

### props 参数

包含所有可能需要升级的数据：

```typescript
{
  config: { ... },       // 或 null
  secrets: { ... },      // 或 null
  actions: [
    {
      id: 'abc',          // 不可编辑，否则 Companion 会忽略其他更改
      controlId: 'bank:def', // 只读
      actionId: 'my-action',
      options: { ... },
    },
  ],
  feedbacks: [
    {
      id: 'abc',          // 不可编辑
      controlId: 'bank:def', // 只读
      feedbackId: 'my-feedback',
      options: {
        valA: { isExpression: false, value: 1 },
      },
      isInverted: { isExpression: false, value: false },
    },
  ],
}
```

**注意**：动作和反馈的 options 对象与回调中的形式大不相同，值被包装为 `{ isExpression, value }` 形式。

### 返回值

返回描述哪些动作/反馈已更改以及新配置对象的对象：

```typescript
{
  updatedConfig: null | object,
  updatedSecrets: null | object,
  updatedActions: Action[],
  updatedFeedbacks: Feedback[],
}
```

返回值可以是新对象、克隆对象或原地修改的 props 对象。Companion 据此判断哪些已更改，避免对未更改项进行过度处理。

## 处理表达式

由于动作和反馈的选项在升级脚本中是包装后的值或表达式，需要谨慎处理以确保升级安全，不会破坏或丢失用户定义的表达式。

`@companion-module/base` 提供的辅助工具：

- `FixupNumericOrVariablesValueToExpressions`：如果字段之前是 textinput 且期望数字或包含数字的变量，此工具可将包装值转换为新的包装值（或表达式），用于数字输入字段。

## Boolean Feedback 转换

如果计划将 advanced feedbacks 转换为 boolean feedbacks，有专门的指南和辅助函数。

`CreateUseBuiltinInvertForFeedbacksUpgradeScript` 可用于生成升级脚本，将现有的 invert 复选框转换为内置系统：

```typescript
CreateUseBuiltinInvertForFeedbacksUpgradeScript({
  myfeedback: 'invert',
  another: 'inverted',
})
```
