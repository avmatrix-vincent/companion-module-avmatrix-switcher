# Companion 模块开发 - 运行时权限

> 文档来源：https://companion.free/for-developers/module-development/connection-advanced/permissions

## 概述

从 API 1.12 开始，模块运行时应用了一些限制性权限。目的是限制 Node.js 运行时的某些危险能力，以便向用户警告需要这些权限的模块。

类似于手机安装应用时提示接受权限列表。

## 启用权限

在 `companion/manifest.json` 的 `permissions` 对象中添加需要的权限：

```json
"permissions": {}
```

**注意**：开发时也会应用这些权限。但启用调试器时，权限会被禁用。发布前确保在不启用调试器的情况下测试模块。

## 可用权限

### Worker threads

如果模块需要使用 worker threads：

```json
"permissions": {
  "worker-threads": true
}
```

### Child Processes

如果模块需要生成子进程：

```json
"permissions": {
  "child-process": true
}
```

建议尽量避免使用子进程，因为生成的进程会绕过应用到模块的所有限制，会被报告为危险操作。

### Native addons

如果模块需要使用原生插件：

```json
"permissions": {
  "native-addons": true
}
```

### Filesystem access

如果需要读取更多文件系统内容或写入文件系统：

```json
"permissions": {
  "filesystem": true
}
```

未来版本的 Companion 可能要求用户为每个连接授予特定路径的访问权限。目前这只是一个请求，用户可能授予也可能不授予。

### Insecure OpenSSL algorithms

在极少数情况下，模块可能需要与使用已弃用加密算法的旧设备通信：

```json
"permissions": {
  "insecure-algorithms": true
}
```

这目前相当于使用 `--openssl-legacy-provider` 参数运行进程。

## 权限声明示例

```json
{
  "name": "my-module",
  "permissions": {
    "worker-threads": true,
    "filesystem": true
  }
}
```
