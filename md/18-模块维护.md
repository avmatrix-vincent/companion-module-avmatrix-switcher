# Companion 模块开发 - 模块维护

> 文档来源：https://companion.free/for-developers/module-development/module-lifecycle/

## 重命名模块

偶尔需要重命名模块，例如为了更包容地支持更多设备，或制造商发布了新设备。

### 重命名步骤

1. **在 module-development Slack 频道申请新名称**
   - 确保新名称符合 companion-module-manufacturer-product（或 companion-module-manufacturer-protocol）结构

2. **团队会协助重命名 GitHub 仓库**

3. **更新相关文件**
   - 更新 package.json 中的名称和 URL
   - 更新 companion/manifest.json 中的名称和相关字段
   - 将旧名称添加到 companion/manifest.json 的 legacyIds 数组中。这让 Companion 知道重命名操作，现有用户会自动迁移

4. **发布新版本并提交审核**

**重要提示**：重命名时不得减少升级脚本的数量。计数会从旧模块名称继续，移除任何升级脚本会导致许多用户跳过新的升级脚本。

## 更新 Node.JS 版本

### 背景

Node.js 经常发布新版本，大版本跳跃可能包含破坏性变更。从 Companion 3.0 开始要求模块兼容 Node.JS v18。从 @companion-module/base v1.11 开始支持 Node.JS v22。

开发模块时需要安装相近版本的 Node.js。Companion v4 支持模块使用 v18 和 v22，但可能提供与你使用的不同的次要版本。

**注意**：Companion 运行模块时使用的是 Companion 分发的 Node.js 版本，而非你自行安装的版本。

### 修改模块的 Node.js 版本

Companion 通过 companion/manifest.json 的 runtime 对象中的 type 属性确定兼容的 Node.js 版本。有效值为 node18 或 node22。未知值会导致模块在 Companion 中无法运行。

确保 @companion-module/base 依赖版本与 Companion 版本兼容。兼容性表格在 README 中列出。

如果使用 TypeScript，应更新预设以获得合理的 target 和 lib 值。@companion-module/tools 中的配置预设为每个支持的 Node.js 版本提供了对应版本。

如果 package.json 中有 engines 字段，确保其值合理。

完成后在 Companion 中测试，确保一切正常。

## 使用未发布的 @companion-module/base 版本

如需使用尚未发布的 @companion-module/base 版本，可通过指定 Git 依赖或本地路径的方式安装。但发布到官方仓库前，必须切换到已发布的稳定版本。

## @companion-module 库说明

### 主要库

| 库名 | 用途 |
|------|------|
| @companion-module/base | 模块插件 API。小巧、稳定、保守版本控制。编写模块时只需依赖此库。 |
| @companion-module/tools | 构建工具、TypeScript 预设、ESLint/Prettier 配置。开发依赖。 |
| @companion-module/host | Host 端包装器，在 Companion 内部运行插件。处理 API 版本兼容性。Companion 自身使用。 |

### 何时更新

- **@companion-module/base**：有新功能或 bug 修复时需要。查看 changelog 了解变更。
- **@companion-module/tools**：构建工具更新时。通常不影响运行时行为。

### 历史背景

模块 API 的设计目标是将插件 API 保持最小化和稳定化，同时允许 Host 端自由演进。这种分离确保了模块开发者不需要频繁适配 Companion 核心变更。

## 从 Companion 2.x 升级

### 背景

Companion 3.0 引入了全新的模块 API（基于 @companion-module/base），与 2.x 时代的模块架构完全不同。2.x 模块无法直接在 3.0+ 中运行。

### 升级步骤

1. 使用 TypeScript 模板或 JavaScript 模板创建新模块结构
2. 将原有逻辑迁移到新的 InstanceBase 类结构
3. 使用新的 API 重新定义动作、反馈、变量和预设
4. 编写升级脚本以迁移用户现有配置
5. 按照打包和发布流程重新发布模块

详细迁移指南可参考 Companion 官方文档的升级说明。
