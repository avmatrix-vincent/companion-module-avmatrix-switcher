# Companion 模块开发 - 模块打包与发布

> 文档来源：https://companion.free/for-developers/module-development/module-lifecycle/

## 模块打包

### 背景

从 Companion 3.0 开始，模块必须使用特殊工具打包。目的是减少模块文件数量和总大小。将模块合并为少量文件通常可将大小从数 MB 减少到数百 KB，显著缩短加载时间。

**注意**：构建过程可能引入或暴露导致模块无法运行的问题，分发前务必测试。

### 测试打包

使用推荐模板时，运行以下命令打包：

```bash
yarn companion-module-build
```

成功后在模块根目录生成 pkg/ 文件夹和 `<module-name>-<version>.tgz` 文件。模块名称和版本取自 package.json。

如需调试打包后的代码而非开发代码，在模块文件夹中创建空文件 DEBUG-PACKAGED。Companion 会从 pkg 读取代码。

**提示**：打包可能导致错误堆栈不可读或日志中显示大量代码。使用 DEBUG-PACKAGED 时，运行 `yarn companion-module-build --dev` 可生成更大的构建文件，保留原始行号和格式，便于阅读输出。

### 分发打包

运行 `yarn companion-module-build`（不加 --dev）生成 .tgz 文件。用户可从 Companion Modules 页面加载此文件，Companion 会像从商店获取一样运行它。

### 自定义打包

复杂模块可调整打包设置。在模块文件夹中创建 build-config.cjs 文件，内容为 `module.exports = {}`。

#### 更改 __dirname

默认情况下 __dirname 被替换为 /，所有路径相对于打包后的主文件。设置 `useOriginalStructureDirname: true` 可保留原始路径。

#### 包含额外数据文件

从 API 1.12 起，模块默认仅有模块文件夹的只读访问权限。如需打包额外的文本文件或其他格式文件：

```js
module.exports = {
  extraFiles: ['*.txt'],
}
```

可使用任何 glob 模式定义要复制的文件。所有文件将复制到包的根文件夹。确保文件名不冲突，不要复制不需要的文件。

#### 使用原生依赖

原生依赖无法像 JS 依赖一样打包。需要在 manifest.json 中声明权限。

仅支持发布预构建二进制文件的 npm 包。

- 使用 prebuild-install 的库：不兼容，如有需要请联系团队
- 使用 pkg-prebuilds 的库：

```js
module.exports = {
  prebuilds: ['@julusian/freetype2'],
}
```

- 使用 node-gyp-build 的库：首选设置 `useOriginalStructureDirname: true`，或标记为 external：

```js
module.exports = {
  externals: [
    {
      'node-hid': 'commonjs node-hid',
    },
  ],
}
```

#### 使用额外插件

```js
module.exports = {
  plugins: [new webpack.ProgressPlugin()],
}
```

#### 禁用压缩

某些库在压缩时会出错：

```js
module.exports = {
  disableMinifier: true,
}
```

建议保持开启以避免安装体积膨胀（压缩可减小三倍大小），但如有合理原因可禁用。

#### 使用 worker threads

Worker threads 需要自己的入口点，目前仍在研究中。如有需求请联系团队。

## 模块发布

### 首次发布

如果是模块的首次发布，需要在 Slack 的 #module-development 频道请求仓库。消息中需包含 GitHub 用户名和模块名称（manufacturer-product 格式）。

获得仓库并推送代码后，即可发布新版本。

### 发布新版本

模块测试完成并准备分发时，按以下步骤提交审核：

1. **更新 package.json 版本**
   - 使用 major.minor.patch 格式（如 1.2.3）
   - 参考 Versioning of Modules 指南

2. **（可选）更新 companion/manifest.json 版本**
   - 非必须，构建过程会用 package.json 的版本覆盖此值

3. **创建 Git 标签**
   - 版本号前缀加 v（如 v1.2.3）
   - 可通过 GitHub 创建 release，或在本地创建标签并推送到仓库

4. **在 Bitfocus Developer Portal 提交新版本**
   - 使用 GitHub 登录
   - 侧边栏进入 My Connections，选择模块
   - 点击 Submit Version
   - 选择 Git Tag
   - （可选）如为 beta 版本，勾选 Is Prerelease
   - 点击 Submit 提交审核，版本状态应显示为 Pending

### 审核注意事项

- 仅提交到开发者门户的版本才会被审核
- 审核由志愿者完成，审核时间取决于成员可用性和代码变更复杂度
- 如需调整，会通过开发者门户收到反馈
- 审核通过后，新版本立即可供 Companion v4.0.0+ 用户下载
